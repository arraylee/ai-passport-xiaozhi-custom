# Trae Card 网页量产烧录

纯浏览器量产工具：使用 Web Serial + `esptool-js` 连接 ESP32-C3，读取本机 MAC，在浏览器内生成
与 ESP-IDF `nvs_partition_gen.py` 兼容的 `cardid` NVS 分区，并与 `scripts/release.py` 生成的正式
release ZIP 中六个固定分区一起烧录。

此页面用于量产身份初始化，会另外写入 `cardid@0x356000`。已有身份设备需要保留身份进行
固件升级时，请使用仓库根 README 的六段 CLI 更新流程；本页面不是保留旧身份的升级入口。

## 使用

```bash
cd tools/web_flasher
npm ci
npm run dev
```

用最新版 Chrome/Edge 打开 Vite 输出的 `localhost` 地址。正式部署必须使用 HTTPS；Web Serial
不能从普通 HTTP 页面使用。

1. 选择 `scripts/release.py` 生成的正式 release ZIP。
2. 手动输入该设备的 Key/DeviceSecret；ProductKey 固定为 `folotoy`，HardwareVersion 固定为
   `v1.0.0`，页面只读显示。
3. 连接处于可下载状态的 ESP32-C3，SN 自动取本机 MAC。
4. 确认自动读取的 SN 后点击“生成身份并烧录”。
5. 保存浏览器自动下载的 `cardid_<SN>.csv` 台账。

烧录地址锁定为当前项目布局：

| 地址 | 内容 |
| ---: | --- |
| `0x000000` | bootloader |
| `0x008000` | partition table |
| `0x010000` | app |
| `0x356000` | 浏览器本地生成的 16KB cardid |
| `0x35a000` | 用户头像运行时分区（仅校验布局，不预写） |
| `0x3fa000` | imgava |
| `0x500000` | 只读共享素材与 BDF1 正文字库 |
| `0x600000` | 只读标题字库与动态形象 |

载入 ZIP 时会检查全部文件的 `SHA256SUMS`、六段 manifest、两份刷写参数、十一分区的
类型/子类型/地址/容量/标志、完整字体许可及其应用内原文，并验证 PTP1 图包每个资产的
CRC、SHA-256、原生 PSR1 行数据及应用内匹配指纹。缺少 manifest、只有 BIN 文件、混搭应用
和图包、损坏资源、目录嵌套或重复文件都会在连接刷写前被拒绝。文件哈希用于一致性检查，
并不是发布者的数字签名。

选择新 ZIP 时会立即清除旧包并禁用烧录，取消选择或校验失败后也不会回退到旧包；连续选择时仅
最后一次校验结果生效。连接和烧录期间锁定输入，重复点击不会创建第二个串口操作。每次烧录都会
固定固件、身份和台账快照，断开清理结束后才允许下一次连接。

工具不会执行整片擦除，不会把 ProductKey 或 DeviceSecret 写入日志或上传网络。Key 必须由操作员
手动输入，按 UTF-8 编码必须为 1–64 字节且不能含 NUL（多字节字符不能按字符数判断）；无效时
烧录按钮保持禁用。成功烧录后输入框会自动清空，避免下一台误用。生成器兼容性
测试以 ESP-IDF 5.5.3 所带
`esp_idf_nvs_partition_gen 0.1.9` 的固定输出 SHA-256 为基准。

烧录完成后，工具使用 ESP32-C3 RTC 看门狗寄存器序列执行芯片级软件重启；若软件命令发送失败，
才回退到 USB 串口 DTR/RTS 硬复位。这样不依赖部分治具上未连接或无效的自动复位控制线。

## 验证

```bash
npm test
npm run build
```

测试直接运行 `main.ts` 的真实事件处理器，以可控异步加载/串口边界验证换包、取消、过期结果、
重复点击、失败恢复、固件与台账一致性；另外覆盖多字节 Key 边界、NVS 固定兼容字节，以及仅写
六段固件加最后一段 cardid、`eraseAll: false`。这些测试不访问真实硬件。

`dist/` 是可部署的静态站点。量产环境应锁定并审计依赖、通过 HTTPS 内网托管，并将下载台账立即
导入受控 MES；浏览器下载目录中的明文台账文件同样属于密钥材料。

.10 字库包使用 CPR1 v3，并在 petart +0x10000 放置 BDF1 正文字库。加载器会核对内外层校验值、字符资源边界以及应用中匹配指纹，拒绝缺失或混搭字库。旧版资源包的验证兼容性仍保留。
